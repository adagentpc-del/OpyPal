Build a production ready CRM and outbound sales automation platform for A3 Visual focused on cold outreach, follow up automation, reply detection, template management, queue based sending, and lightweight pipeline management.

The system must be clean, fast, simple to use, easy to edit, and optimized for minimal admin work. The goal is that the user can select contacts, choose an initial email template, approve the first send, and let the system intelligently manage follow up unless a real response is detected or the user manually changes the lead.

This is being built for one primary user first, but the architecture should support future multi user and team expansion.

CORE GOAL

Create an outbound sales CRM that does all of the following:

1. Stores contacts, companies, templates, follow up sequences, message history, lead status, and automation states
2. Connects to Outlook so the system can send, thread, detect replies, and stop automation when a real reply occurs
3. Allows the user to choose an initial template and associated follow up sequence
4. Automatically schedules follow ups at:
   - 3 days
   - 7 days
   - 14 days
   - 1 month
   - 3 months
   - 6 months
   - 1 year
5. Sends early follow ups in the same thread
6. Allows longer term follow ups to become reactivation style messaging
7. Stops automation if a real inbound reply is detected or if the lead status is manually changed
8. Ignores out of office and other auto replies
9. Supports queue based throttled sending to protect domain health
10. Makes everything editable globally and at the contact level
11. Provides clear dashboards for active, paused, stopped, replied, and performance by template and sequence
12. Keeps the UI simple and not bloated

PRODUCT POSITIONING

This is not just a CRM.
It is an A3 Sales OS with outbound automation, reply intelligence, and follow up orchestration.

It should feel like:
- easy enough for a non technical sales operator
- structured enough to scale later
- intelligent enough to reduce admin and manual tracking
- safe enough for deliverability and outreach quality

CORE BUSINESS LOGIC

Initial Send Workflow

When user selects one or more contacts and chooses an initial template:

1. Show preview of the initial email
2. Allow user to edit subject and body before approval
3. Once approved, send the initial email via Outlook
4. Save full metadata including thread/conversation identifiers
5. Automatically attach the contact to the selected follow up sequence
6. Generate the future scheduled follow up emails
7. Mark contact status as:
   - Initial Sent
   - then Follow Up Active if sequence is active
8. Show next scheduled follow up date in contact record

Follow Up Schedule Rules

Default cadence for every active sequence:
- Step 1 = 3 days
- Step 2 = 7 days
- Step 3 = 14 days
- Step 4 = 1 month
- Step 5 = 3 months
- Step 6 = 6 months
- Step 7 = 1 year

Threading behavior
- 3 day, 7 day, 14 day, 1 month follow ups should send as replies in the same thread
- 3 month, 6 month, 1 year follow ups may either reply in thread or start a reactivation style message depending on sequence configuration
- Default best practice:
  - 3 day, 7 day, 14 day, 1 month = same thread
  - 3 month, 6 month, 1 year = reactivation style and allowed to use updated subject line

Stop Conditions

Automation must stop automatically when:
- a real human inbound reply is detected
- contact status changes to a status with stopsAutomation = true
- user manually clicks stop sequence
- contact is marked Do Not Contact
- contact is marked unsubscribed
- contact is marked bounced
- contact is marked Meeting Booked
- contact is marked Closed Won
- contact is marked Closed Lost

Automation may pause when:
- user clicks pause
- contact status is Paused
- system flags uncertain reply needing review
- account level pause is enabled manually

Auto Reply Detection

The system must not count these as a real reply:
- out of office
- automatic replies
- calendar auto responses
- read receipts
- delivery confirmations
- spam filter notifications
- mailbox full errors
- exchange auto acknowledgements
- vacation responders

The system should count these as real replies:
- human written replies
- short replies such as “yes” or “send info”
- “not interested”
- forwarded human replies
- meeting confirmations
- question based responses
- replies with attachments or custom text

Reply classification behavior
Build a reply classification layer that uses:
- email headers where available
- common auto reply patterns
- subject line patterns
- body pattern detection
- provider metadata
- heuristic classification
- optional lightweight AI classification if needed

If confidence is high that the reply is auto generated, do not stop automation.

If confidence is high that the reply is human, stop automation.

If confidence is uncertain, place it in Reply Review Queue and pause further follow up until reviewed.

Manual Override and Contact Level Controls

In each contact record, allow the user to:
- view full message history
- see current sequence and current step
- see next scheduled send
- edit next send date
- skip next step
- send next step now
- rewrite one queued email only
- swap contact into a different sequence
- pause sequence
- stop sequence
- resume sequence
- convert queued email to draft only
- update lead status
- add notes
- manually mark as replied or not interested if needed

This is important because the user wants flexibility, but minimal admin.
The system should automatically track as much as possible from Outlook so the user does not have to manually update every field.

Global Template Editing

User must be able to:
- create initial templates
- create follow up sequences
- create multiple sequences per vertical
- assign a default sequence to each initial template
- edit subject lines and body copy
- use merge tokens
- duplicate templates
- archive templates
- activate or deactivate templates
- preview templates with sample contact data

When editing templates or sequences, provide option:
- apply changes only going forward
- apply changes to already queued unsent emails

SENDING AND DELIVERABILITY RULES

This is important. The system must send in a controlled queue.

Sending windows
Default settings:
- weekdays only
- local business hours
- default window 8:15 AM to 4:45 PM
- use contact timezone when available
- otherwise use user timezone

Throttling
- never blast all selected contacts at once
- stagger sends gradually
- minimum delay between sends should be configurable
- randomize within a small range for more natural sending
- respect per day and per hour send caps
- optional domain level throttling
- prevent duplicate sends to same contact
- prevent multiple active sequences on same contact unless explicitly allowed

Queue behavior
If a user selects a group, queue them for controlled sending rather than instant bulk send.

Each scheduled email should move through:
- queued
- ready
- sending
- sent
or
- paused
- skipped
- failed
- review_required

Sync behavior

- let user manually pause if needed

AUTOMATION ENGINE REQUIREMENTS

Build a background processor that:
1. checks scheduled emails regularly
2. validates contact is still eligible
3. confirms no stop conditions triggered
4. confirms send window is valid
5. applies throttling logic
6. sends via Outlook
7. logs message metadata
8. updates contact sequence state
9. schedules next step if applicable

Before any scheduled send, check:
- contact is not marked replied
- no human reply has been detected
- no stop status applied
- no bounce or unsubscribe flag
- sequence is active
- review queue does not block this contact

SMART DEFAULTS FOR MINIMAL ADMIN

Because the user wants the system to do most of the work automatically, implement these defaults:
- auto track inbound and outbound from Outlook where possible
- auto classify replies
- auto stop when human reply is confidently detected
- auto pause when reply is uncertain
- auto log manual Outlook activity if detected
- auto advance sequence state
- auto surface only exceptions that need attention
- keep manual admin optional, not required

The system should reduce busywork, not create more.
